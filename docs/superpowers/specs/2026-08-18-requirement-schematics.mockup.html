specboard
requirement schematics — a Claude-drawn animation beside each requirement, so the idea reads without prose
Each requirement keeps its authored text, and gains a small looping schematic drawn from that text — generic shapes in one house style, not a copy of the real UI. It explains the idea of the action for readers who don't want to parse the prose. It is decoupled from the app on purpose; what keeps it honest is that it is pinned to the requirement text by a hash — reword the text and the board marks the picture stale until staff redraws it (try the button on R2).

Checking a todo moves it under Done

Completion is a move, not a restyle: when its box is checked, the item leaves the To-do list entirely and settles under Done, struck through.

Done keeps history visible without cluttering what is still left to do, and the count of items left drops by one the moment the box is checked.

How it's produced — and how it can't silently rot

1 · author the requirement
text is the source of truth, as always. Human owns the meaning
2 · staff draws the SVG
a claude pass turns the text into a house-style animated SVG (detached job, like scan/crawl)
3 · cache by text-hash
the SVG is committed beside the PRD, stamped with a hash of the text it was drawn from
4 · render beside the prose
the board inlines the SVG next to the requirement — read and watch together
5 · text changes → STALE
hash mismatch is computed on build; the picture is marked stale, never shown as if current
6 · staff redraws
a viz pass re-draws stale ones and re-stamps the hash. Human never chases it
The schematic is decoupled from the app (so ag-grid is never rebuilt) but pinned to the requirement text by a hash. That hash is the honesty mechanism: this product computes drift and refuses to hide it, and the picture is held to the same rule as everything else — reword the text and the board says the picture is stale rather than letting a wrong picture pass for right. It explains the idea; it never claims to be the proof (the test still owns that).
