specboard flow composer — chain unit beats into a flow; the board hands you the prompt, it never writes the test (R15)

Every unit test already proves a beat — a Given, a When, a Then. This composer treats each beat as a node and lets you chain nodes into a flow: click nodes from the library to append them, and the composer checks every joint — beat N's Then must supply beat N+1's Given. A joint that doesn't line up shows a gap and names the node that would fill it. When the path holds, the output is a ready kg-e2e prompt — the board composes the spec of the flow, never the flow test itself.

Node library

one node per beat the screen's tests already prove — derived from the unit tests and behavior blocks, nothing hand-registered. Click a node to append it to the chain.
what makes two nodes the same node element archetype (list item, toggle, picker) × state signature (an unchecked item ≠ a checked one) × structure signature (an item with sub-items ≠ one without). Two identical unchecked todos are ONE node.
