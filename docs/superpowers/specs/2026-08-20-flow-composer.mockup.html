specboard flow composer v2 — chain unit beats into a flow; the board hands you the prompt, it never writes the test (R15)

Every unit test already proves a beat — a Given, a When, a Then. This composer treats each beat as a node and lets you chain nodes into a flow: click nodes from the library to append them, and the composer checks every joint — beat N's Then must supply beat N+1's Given. A joint that doesn't line up shows a gap and names the node that would fill it. When the path holds, the output is a ready kg-e2e prompt — the board composes the spec of the flow, never the flow test itself. v2 answers the 2026-08-21 round: screen tabs + search in the library, unproven outline beats and a cold-start state, insert-points and reorder on the chain, a named flow with a one-liner Claude handoff (draft kept in the browser only), and the revised player below.

Node library

one node per beat, derived from the behavior blocks and the tests — nothing hand-registered. A solid node is proven (a passing assertion holds it). A dashed outline node is a behavior-block beat no test proves yet — chainable, and the prompt then makes the flow establish it red-first.
what makes two nodes the same node element archetype (list item, toggle, picker) × state signature (an unchecked item ≠ a checked one) × structure signature (an item with sub-items ≠ one without). Two identical unchecked todos are ONE node.

The flow — one path through the nodes

starts from the screen's fixture Given. Every joint is checked: Then ⊇ next Given. Try appending “tick a sub-task from the detail” before opening the detail — the joint gaps, and the library highlights the node that fills it. The ＋ under a joint arms an insert-point: the next library click lands there.
