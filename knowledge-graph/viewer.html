What am I looking at?

A live map of what this product promises and what actually proves it — regenerated from source (specs, memories, test files), never hand-kept. Five tabs across the top:

  • Summary — the plain-language scorecard: every product promise and whether an automated test proves it today.
  • Feature tests — one capability, many scenarios. Each feature's FE-unit / BE-unit / end-to-end / cache coverage, traceable to source.
  • Flow tests — one long end-to-end journey per test (e.g. change a scenario → run → save → reload), grouped by flow. No unit/cache columns — just the journey and its steps.
  • Knowledge map — the governing docs, instructions and memories, cross-linked, each showing its created / updated dates and a stale flag when it hasn't been reviewed in 90+ days.
  • Conflicts — contradictions the scanner found across docs/code (one fact stated two ways), each side dated so you can resolve toward the most-recent.

Feature test vs flow test

A feature test checks one capability under different scenarios; a flow test walks a whole user journey end-to-end across several features. A case declares which it is with kind: in its *.cases.yaml, and appears in exactly one of the two tabs.

A requirement is proven when at least one test covers it, else it shows as a gap. A feature's four coverage dots are FE-unit, BE-unit, E2E and cache. Every count is computed from source — hiding node types in Settings › Display does not change them.

Running tests (when served with npm run serve)

▶Watch — runs one test in a maximized, paced, headed browser you can watch. Single test only.
⚡Run — headless and fast. Tick several cases (checkboxes) or use ⚡ Run all on a group for a batch — batches run headless, in parallel where safe.

Read-only cases run in parallel; cases that mutate shared data run one at a time within a batch.

Settings (top-right)

One panel holds it all: Status — when the graph and test results were last synced (a ⚠ dot on the button warns when they're stale) and whether runs reuse one server or spin a fresh stack each time; Appearance — an Auto / Light / Dark theme toggle (Auto follows your system); your read-only GitHub token for loading private evidence screenshots; and Display toggles that visually hide FE-unit / BE-unit / cache nodes (counts stay honest).
