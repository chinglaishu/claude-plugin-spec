1 · Requirements the source of truth

R1A draft version is editable; a live version is read-only›

The page's editability is governed by the selected version. On a live (published) version the whole surface is read-only: a "Locked" indicator shows and there is no Edit control, no editable Net rent, no Run plan. On a draft version (the version is not locked) the Edit control, per-unit Net rent editing, and Run plan are available.

  • The version pill states which it is. getByRole('combobox', { name: /Property version/ }) — name ends "draft" or "live"
  • The read-only indicator on a live version reads "Locked". data-testid="read-only-indicator"
  • Draft is the state under test here; the test seeds a draft version ("E2E Golden Draft").

Assert: on the draft, an Edit control is present getByRole('button', { name: /^Edit$/ }) and, after entering edit mode, the Net rent cells and Run plan appear (R6). A test that only proves the page painted proves nothing.

proven by Draft editing flow Guardrails
R2A re-baseline notice, if present, must be dismissed before the page is usable›

On load the property may raise a "Re-baselined to …" dialog that overlays the whole page behind a modal scrim. Until it is dismissed, every control beneath it is unclickable — and because visibility checks do not detect occlusion, a test that skips it passes while stuck behind the popup.

  • Dismiss control: a "Got it" button. getByRole('button', { name: 'Got it' })
proven by Guardrails — reworded since last run · re-run to re-prove
R3The key-metrics surface renders real, period-scoped values›

A row of metric cards summarises the leases commencing in the selected period. Each carries a real value (a count, money, or a %), computed over the period-filtered rows.

  • Commencing leases — a count.
  • Commencing net rent — summed contracted net rent, per-month and per-year.
  • Renewal share — probability-weighted, by rent and by area.
  • Reversion — cash and effective.

metric-rent sums the contracted net rent, not the editable lever — so it does not move on an edit until Run plan re-stamps the rows. golden.json.metrics

proven by Key metrics
R4The grid lists the property's units/leases, with the modelling columns›

The rent-roll grid shows one row per unit×lease-cycle, grouped by commencing period, with a pinned Total row. AG Grid treegrid — target .ag-row / .ag-cell[col-id]; leaf id = unitId::c{cycle}

Selecting a specific investment year shows an exact set of units/leases. Assert the exact list, not "there are rows". golden.json.byYear

proven by Draft editing flow
R5Editing a draft unit's Net rent updates its Gross rent in-cell›

In edit mode, the Net Rent cell of a unit is editable. Typing a new Net rent immediately updates that unit's Gross Rent cell client-side (a value-getter), before any server round-trip. col market_rent_open → gross_rent_open

Assert the Gross Rent cell changes to the golden "after" value when the Net rent is set to the golden edit value. golden.json.edit

proven by Draft editing flow
R6Run plan recomputes Gross Rental Income per investment year›

This is the heart of the screen. With the year basis on Investment (periods IY1, IY2, …), after editing a unit's Net rent (R5) the Run plan button enables; clicking it recomputes the projection and the Gross Rental Income series changes.

  • Gross Rental Income is the compare chart's series, not a metric tile. It is the AssetPlanCFCompareChart plotted with metric="gross_rental_income" — a "Base" line vs a "Plan" line once a plan is run. legend data-testid="compare-chart-legend"
  • Exact per-year GRI is read from the chart's underlying series, not the rounded on-canvas label.
  • Assert: for each investment year, GRI moves from its golden before to its golden after once the plan is run. golden.json.gri
